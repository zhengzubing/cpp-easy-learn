# 条款一：理解模板类型推导

## 情景一：ParamType是一个指针或引用，但不是通用引用

```
template<typename T>
void f(T& param);               //param是一个引用

const int cx=x;                 //cx是const int
f(cx);                          //T是const int，param的类型是const int&
///////////////////
template<typename T>
void f(const T& param);         //param现在是reference-to-const

const int cx = x;               //如之前一样
f(cx);                          //T是int，param的类型是const int&
```
将一个const对象传递给以T&类型为形参的模板安全的

## 情景二：ParamType是一个通用引用
```
template<typename T>
void f(T&& param);              //param现在是一个通用引用类型
```
如果expr是左值，T和ParamType都会被推导为左值引用

## 情景三：ParamType既不是指针也不是引用
会成为它的一份拷贝——一个完整的新对象
**expr的常量性constness或易变性volatileness在推导param类型时会被忽略**：因为expr不可修改并不意味着它的拷贝也不能被修改。**只有在传值给形参时才会忽略const（和volatile）**.

```
const int cx=x;                 //如之前一样
f(cx);                           //T和param的类型都是int
```

## 数组实参

```

void f(T param);                        //传值形参的模板
```

## 请记住：

在模板类型推导时，有引用的实参会被视为无引用，他们的引用会被忽略
对于通用引用的推导，左值实参会被特殊对待(T和ParamType都会被推导为左值引用)
对于传值类型推导，const和/或volatile实参会被认为是non-const的和non-volatile的
在模板类型推导时，数组名或者函数名实参会退化为指针，除非它们被用于初始化引用



# 条款2 理解 auto 类型推导

auto类型推导和模板类型推导的真正区别在于，auto类型推导假定花括号表示std::initializer_list而模板类型推导不会这样
```
auto x3 = { 27 };               //类型是std::initializer_list<int>
```

## 请记住：

**auto类型推导通常和模板类型推导相同**，但是auto类型推导假定花括号初始化代表std::initializer_list，而模板类型推导不这样做
在C++14中auto允许出现在函数返回值或者lambda函数形参中，但是它的工作机制是模板类型推导那一套方案，而不是auto类型推导

# 条款3 理解 decltype

```
template<typename Container, typename Index>    //可以工作，
auto authAndAccess(Container& c, Index i)       //但是需要改良
    ->decltype(c[i])
{
    authenticateUser();
    return c[i];
}
```
返回值类型后置的作用:如果我们按照传统语法把函数返回类型放在函数名称之前，c和i就未被声明所以不能使用。

decltype 和 auto 是 C++ 中两种类型推导工具，但它们的推导规则有一个核心区别：
auto 推导时会忽略变量的引用性、常量性等修饰（类似模板类型推导），需要显式添加修饰符才能保留这些属性。
**decltype 推导时会严格保留变量的原始类型信息，包括引用、常量、volatile 等修饰符**。

decltype(auto) 结合两者特性 —— 用 decltype 的精确性，却遵循 auto 的上下文推导逻辑。
**decltype(auto) 可以看作是 decltype 的 “简化版”，它省去了显式写出表达式的麻烦**.

## 请记住：

decltype总是不加修改的产生变量或者表达式的类型。
对于T类型的不是单纯的变量名的左值表达式，decltype总是产出T的引用即T&。
C++14支持decltype(auto)，就像auto一样，推导出类型，但是它使用decltype的规则进行推导。


# 条款4 学会查看类型推导
template<typename T>                //只对TD进行声明
class TD;                           //TD == "Type Displayer"
如果尝试实例化这个类模板就会引出一个错误消息，因为这里没有用来实例化的类模板定义。为了查看x和y的类型，只需要使用它们的类型去实例化TD：


TD<decltype(x)> xType;              //引出包含x和y
TD<decltype(y)> yType;              //的类型的错误消息
**我使用TD<decltype(x)> 的结构来命名变量，因为这样它们产生的错误消息可以有助于我们查找**(他是准确的)

std::type_info::name的结果并不总是可信的
在std::type_info::name和IDE失效的地方，Boost TypeIndex库（通常写作Boost.TypeIndex）被设计成可以正常运作


## 请记住：

类型推断可以从IDE看出，从编译器报错看出，从Boost TypeIndex库的使用看出
这些工具可能既不准确也无帮助，所以理解C++类型推导规则才是最重要的
